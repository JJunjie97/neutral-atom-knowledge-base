# 中性原子量子计算数据库实施计划（历史初版）

## 目标边界

最终目标是一个可搜索、可追踪、可点击全文的中性原子量子计算知识库。第一阶段只解决底座问题：文献实体去重、参考文献抓取、引用关系、时间线和可审计的数据质量。

第一阶段的“完整”定义为：

- 综述 BibTeX 的 659 条记录全部进入数据库，不能因缺 DOI 而丢失。
- 每条记录保留 BibTeX key、原字段、正文引用章节和所有外部 ID。
- 对能够匹配的种子论文抓取一跳参考文献。
- 同一论文的 DOI、arXiv、OpenAlex 等标识合并为一个节点。
- 能导出完整一跳图和去重后的种子论文实体之间的子图。
- 所有未匹配、模糊匹配、空参考列表都有审计清单。
- 抓取支持缓存、退避、限流和断点续跑。

## 阶段 1：种子库与引用图（当前）

### 1A. 本地种子数据

- 解析 BibTeX 的花括号、引号、单行条目和裸月份等混合格式。
- 规范化 DOI、arXiv ID、标题和年份。
- 扫描各 `section_*.tex` 中的 `\cite...`，生成论文到综述章节的映射。
- 写入 SQLite，不修改原始 `.bib` 和 `.tex`。

### 1B. 外部实体解析

- DOI 使用 OpenAlex 批量精确查询。
- 无 DOI 或 DOI 未命中的条目使用标题检索。
- 标题候选结合年份和作者计算置信度。
- 自动接受与人工复核分开，保留候选和评分证据。

### 1C. 引用关系

- 获取每个已解析种子 Work 的 `referenced_works`。
- 写入有向边 `seed -> reference`。
- 批量补全参考节点的题名、作者、年份、DOI、期刊、开放获取地址、主题。
- 通过标识别名合并“参考节点”和“种子节点”，自然得到种子间互引网络。

### 1D. 验收指标

- `seed_entries = 659`；`seed_works` 为按 DOI/arXiv 去重后的实体数。
- DOI/arXiv 解析覆盖率与原 BibTeX 统计一致。
- OpenAlex 已解析种子数、空参考列表数、未匹配数明确。
- 所有边无自环；同一来源下无重复边。
- 抽查至少 20 篇论文：标题、年份、作者、参考文献数、5 条引用边。
- `needs_review` 必须人工处理或明确保留为未解析，不能降低阈值强行匹配。

## 阶段 2：多源补全与质量对照

- 接入 Semantic Scholar Graph API，优先用 DOI/arXiv 批量解析。
- 将 Semantic Scholar 的 references 与 OpenAlex 做集合对比。
- 接入 Crossref，仅作为 DOI 元数据与出版商参考文献补充。
- 边按来源并集保存；对冲突记录来源、抓取时间和版本。
- 生成覆盖率报告：按年份、期刊、论文类型统计缺失参考文献的模式。
- 对重要但仍缺失的论文，从合法获取的 PDF/LaTeX 中解析参考文献并人工核验。

## 阶段 3：主题、机构与技术路线

- 建立可人工维护的中性原子领域分类，而不是只依赖通用主题标签。
- 初始本体建议包括：
  - 原子种类与能级体系；
  - tweezer/SLM/AOD/光晶格等硬件；
  - Rydberg、交换、光子接口等门机制；
  - 编译、调度、重排；
  - 模拟、数字计算、量子优势；
  - QEC、容错门、解码；
  - 网络与模块化；
  - 公司、实验室、机构、硬件规模和保真度指标。
- 允许一篇论文属于多个主题，并区分“自动标签”和“人工标签”。
- 在引用时间线之外增加里程碑事件表，避免仅以发表年份解释技术演进。

## 阶段 4：原文与 Markdown

- 先存元数据和合法来源链接，再按开放许可获取 PDF/源文件。
- 保存每个文件的来源、许可、下载时间和 SHA-256。
- PDF/LaTeX 转 Markdown 后保留页码或章节锚点。
- 图、表、公式、补充材料单独建资源表，不把所有内容塞进一个 Markdown。
- 引用上下文解析为 `citing passage -> cited work`，这是后续“为什么引用”分析的关键。

## 阶段 5：展示层

展示层从导出的稳定数据接口读取，不直接爬 API。建议分三种视图：

- 星图：交互式引用网络，按年份、章节、主题、机构过滤。
- 时间线：关键论文与硬件指标的演进。
- 文献页：元数据、摘要、全文 Markdown、引用/被引、相关主题与引用上下文。

第一版可用 Cytoscape.js 或 Sigma.js；图布局应支持预计算，浏览器只加载当前子图，避免一次渲染数万节点。Obsidian 可以作为编辑和校对入口，但不应作为唯一数据库。

## 数据治理

- 原始 BibTeX、API 原始响应、规范化表、人工修订分层保存。
- 自动流程永不覆盖人工修订。
- 每次全量构建记录日期、代码版本、API 数据源和质量报告。
- API key 只放环境变量。
- 数据与全文版权分开管理；元数据可公开不代表 PDF 或转换全文可再分发。
