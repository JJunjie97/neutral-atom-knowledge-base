# 引用星图与发展脉络的可视化语义

本文档规定文献星图中“引用方向”和“发展方向”的含义、年份分层布局的异常处理，以及当前数据快照能够支持和不能支持的结论。前端图例、详情面板、数据导出和后续爬虫都应遵守这些约定。

## 两种方向不能混用

数据库和导出文件中的引用边始终保存为：

```text
source（引用者） ──cites──▶ target（被引用文献）
```

例如，论文 B 的参考文献中包含论文 A，则原始边为：

```text
B ──引用──▶ A
```

这是可验证的书目事实，也是 `source`、`target`、图内入度和图内出度的唯一底层语义：

- `out-degree`：该论文在当前图内引用的文献数；
- `in-degree`：当前图内引用该论文的文献数；
- `Graph degree`：二者之和，不等同于 OpenAlex 的全局被引用数；
- OpenAlex `cited_by_count` 和参考文献总数是外部全局统计，可能大于当前图内计数。

“发展脉络”需要让知识从较早工作向后续工作生长，因此显示方向与原始引用方向相反：

```text
target（较早、被引用） ──后续发展──▶ source（较晚、引用者）
```

也就是同一条 `B cites A` 在发展脉络中显示为：

```text
A ──被后续工作采用──▶ B
```

发展方向是由引用关系推导出的导航视图，不是新的引用事实，也不应反向改写数据库中的边。界面和图例应明确区分：

- **Citation direction / 引用方向**：引用者 → 被引用文献；
- **Lineage direction / 发展方向**：被引用文献 → 后续引用工作。

引用只能表明书目关系，不能单独证明思想继承、技术因果或正面支持。发展脉络因此应称为“基于引用关系推导的发展路径”，而不是确定的知识因果图。

## 关系星图

关系星图保留原始 `source → target` 引用方向。为了避免完整图中的大量箭头互相遮挡，建议按可见层级显示：

- 全图、低缩放：使用低透明度连线，优先保证整体结构可读；
- 高缩放：对可分辨的边显示引用箭头；
- hover、selection 和单篇局部图：完整突出直接入边和出边；
- “本文引用的文献”和“引用本文的文献”使用不同颜色，并在图例中用文字说明；
- 互相引用或重合边使用轻微弧线，避免两个方向完全覆盖。

推荐的图例文字是：

```text
A → B：A 引用了 B
本文 → 参考文献：本文引用的工作
引用本文的工作 → 本文：后续或其他工作引用本文
```

单篇局部图可以提供 `全部 / 参考文献 / 引用本文` 三种关系范围。筛选器可能隐藏关联节点时，界面应显示“当前可见数量 / 总关联数量”，不能静默把较小的可见数量描述为全部关联。

## 年份分层的发展脉络

发展脉络以年份为硬分层，例如由左至右排列：

```text
较早年份  →  较晚年份
```

当前实现中，节点颜色由早期年份的青色连续过渡到近期年份的金色，边按 `target → source` 显示发展方向；领域、元素和技术路线仍由左侧多维筛选控制。后续也可以增加可选的“领域色 + 年份轴”编码。每个年份层内根据相邻年份的连接关系排序，以减少交叉。

这个结构不是严格的树：

- 一篇论文可以同时引用多个不同分支，因此有多个“前置节点”；
- 一篇早期论文可以被多个后续方向共同采用，因此会产生分叉；
- 不同分支可以在后续论文中重新汇合；
- 同年引用、互相引用、元数据异常和版本关系会形成横向边或小环；
- 引用关系不保证构成无环图。

因此实现上应将它视为“按年份分层的有向网络”，而不是强行选定唯一父节点的树。可以突出少量骨架边帮助阅读，但不能删除或改写其余真实边；若因性能暂时隐藏边，界面应显示隐藏数量和展开方式。

### 特殊年份情况

| 情况 | 识别方式 | 推荐显示 |
| --- | --- | --- |
| 正常跨年引用 | `source.year > target.year` | 发展视图中反向为较早 → 较晚的实线或曲线 |
| 同年引用 | `source.year == target.year` | 年份层内部弧线；若有完整日期，可仅用于层内排序 |
| 年份逆序 | `source.year < target.year` | 保留边并使用虚线或异常标记，不自动删除 |
| 年份未知 | 任一端缺少年份 | 放入独立的 `Unknown year` 区域，避免伪造年份 |
| 互相引用或版本环 | 两个方向均存在 | 使用双弧线或双向标记，并保留原始记录 |

年份逆序可能来自 online-first 与正式出版年份差异、预印本/期刊版本合并、书目元数据错误或错误匹配。它是数据质量检查信号，不应仅为了让图看起来像树而被修改。

## 当前数据快照的边界

当前核心图包含综述 BibTeX 去重后的 **637 篇核心文献**及其 **4,118 条核心文献互引边**。完整图扩展到约 **14,072 个实体**和 **30,111 条边**，但扩展方式目前只有一层：

- 4,118 条核心文献 → 核心文献；
- 25,993 条核心文献 → 非核心参考文献；
- 非核心文献作为引用者的已抓取边为 0。

这意味着当前完整图抓取了核心文献的参考文献列表和被引用条目的元数据，但没有递归抓取所有非核心文献自己的参考文献列表，也没有完整展开所有后续 citing works。

因此当前可视化可以准确描述：

- 637 篇综述核心文献之间已知的互引关系；
- 这些核心文献直接引用的一层外部文献；
- 当前综述语料范围内可见的历史来源和发展连接。

当前可视化不能声称：

- 14,072 个实体都已经获得完整的参考文献列表；
- 某论文显示的“引用本文”节点是 OpenAlex 中全部 citing works；
- 图中不存在的边就代表两篇论文没有引用关系；
- 当前网络是中性原子量子计算领域的完整历史谱系。

在完成递归扩展前，界面应使用“基于当前综述及其一层参考文献构建的发展脉络”或“当前语料范围内的 citation lineage”等表述。

## 未来递归抓取路线

递归扩展不能简单地无限遍历 OpenAlex，否则节点和边会迅速扩张到与中性原子主题无关的通用物理、算法、器件和数学文献。建议采用可恢复、可审计的分阶段路线。

### 1. 保持身份和边语义稳定

- 继续使用 DOI、OpenAlex ID、arXiv ID 和规范化书目信息去重；
- 始终以 `citing work → cited work` 保存原始边；
- 对预印本与期刊版本保留别名和合并依据；
- 不因可视化需要反向修改数据库边。

### 2. 为每个节点记录抓取覆盖状态

至少记录：

- `references_fetched`：是否已获取该工作的参考文献列表；
- `citing_works_fetched`：是否已主动获取引用该工作的工作列表；
- `crawl_depth`：距 637 篇核心文献的最短扩展层数；
- `provider`、抓取时间、响应状态和失败原因；
- 已知引用总数与当前已入库边数，以便显示覆盖率而不是伪装完整。

### 3. 按优先级扩展参考文献方向

以核心文献为深度 0：

1. 当前一层参考文献为深度 1；
2. 优先扩展被多篇核心文献共同引用、分类高度相关或人工标记的重要深度 1 节点；
3. 再按相同规则选择深度 2 节点；
4. 设置最大深度、最大节点数、最大边数和单次批量预算。

每一批都应支持断点续跑、响应缓存、限速、重试和错误清单，避免长时间运行时看似卡住或重复请求。

### 4. 有选择地补充 cited-by 方向

对核心文献、网络枢纽和用户关注的论文主动获取 citing works，以补足后续影响路径。新增节点仍需经过主题、年份、文献类型、分类相似度或人工白名单筛选。对未主动展开的节点，应继续显示“后续引用未完整抓取”。

### 5. 控制主题漂移

可组合使用以下条件决定是否继续扩展：

- 与中性原子、Rydberg、光镊、量子纠错、编译、网络或光子控制分类的匹配；
- 是否被多篇核心文献引用；
- 与核心文献的最短图距离；
- 出版年份与文献类型；
- 人工维护的必收、排除和边界主题列表。

通用基础文献可以作为叶节点保留，但不一定继续递归展开。

### 6. 发布可复现快照

每次扩展后应重新生成带版本号的数据快照，并在网页中公开：

- 核心文献数、总节点数和总边数；
- 已抓取参考文献列表的节点比例；
- 已主动抓取 citing works 的节点比例；
- 最大抓取深度、筛选规则和生成时间；
- 年份未知、方向异常、身份待复核和请求失败的数量。

这样，发展脉络会随着数据库扩展逐步接近完整，但每个阶段都能清楚说明其证据范围和缺口。
